# field-app

> Generated by the Avani Calibration Engine. Deep conventions live in the enabled plugins; this file is the project-specific layer.

## Architecture

- **Runtime:** ts-nextjs
- **Infra:** vercel
- **Topology:** single-app
- **Correctness bar:** append-only
- **Sensitivity:** protected

## Stage

Enforcement escalates with the project stage. Resolve it from `AVANI_STAGE` (`dev` | `staging` | `production`), falling back to the branch (`feature/*` → dev, `main` → staging, release → production). Check it before prod-affecting actions.

## Commands

```bash
npm run db:migrate:dev      # create + apply a migration in dev
npm run db:migrate:deploy   # apply pending migrations (prod/deploy)
npm run db:reset            # reset the dev database (DEV ONLY)
npm run db:seed             # seed local data
```

## Deploy

- **Target:** `vercel` — a calibration decision, not a per-session choice. It selects the deploy profile that fixes where migrations run, how secrets reach the platform, what is backed up, and the production gate.
- Production is deployed only by CI under the production gate. Sessions and subagents prepare changes (workflow, config, infrastructure code with its plan or diff) and never deploy, apply, or touch a live environment themselves.
- Procedure: the `avani-core` `deployment` skill — three environments, migrate before deploy, forward-only releases, backup before data-shape changes. Role bounds: `.claude/agents/`.

## Invariants (enforced)

- `observations_append_only_never_delete` — Records are never deleted, only superseded with a correction flag.
- `geo_coordinate_fuzzing_public_views` — Public-facing exports fuzz coordinates; exact coords are admin-only.
- `a11y_axe_clean` — Key pages pass an axe accessibility scan with zero violations.
- `observation_id_uniqueness` — Every observation carries a globally unique id (offline-sync idempotency).
- `session_expires_event_plus_24hrs` — Field sessions expire 24h after the event they belong to.

Tests live in `tests/invariants/`. Do not weaken them to make a change pass; if an invariant is wrong, change it deliberately.

## Enabled plugins

`avani-core`, `avani-typescript`, `avani-nextjs`, `avani-postgis`, `avani-clerk`, `avani-offline`, `avani-field-data`

## Gotchas

- Data is **append-only**: never delete or hard-update records; supersede with a correction.
- Location data is **protected**: public views must fuzz coordinates; exact coords are admin-only.
- Never `prisma db push` against a non-dev database; migrations only, applied on deploy.
